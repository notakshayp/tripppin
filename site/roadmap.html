01 / base

One sealed image.
Not a pile of packages.

Tripppin is built as a single signed image, the same on every machine. Updates swap the whole image at reboot, and a bad update rolls itself back.

Secure by default

Read-only system files, SELinux enforcing, Secure Boot, signed images checked before install.

Minimal

Starts from Fedora's minimal bootc base. Only what Tripppin needs is added.

Self-healing updates

Health checks after every update. Three failed boots and it returns to the last good image.

What's inside the image

Tripppin servicesHarness, verifier, shell, orb, installer, trip CLI. Rust, built with cargo-auditable.ours
Model enginellama.cpp built for Vulkan. A -nvidia image variant adds the NVIDIA driver and CUDA.we package
DesktopHyprland and its libraries. Fedora stopped shipping it, so we package and pin it ourselves.we package
BrandingGeneric Fedora release and logo packages replaced with ours: name, boot splash, wallpaper.ours
Fedora bootc 45, minimalKernel, systemd, SELinux, drivers, bootc, greenboot. Pinned by digest.upstream

Apps install as Flatpaks, which are sandboxed and never touch the system image. Command-line tools go into a container with Toolbx. The AI installs apps the same way.

Why not the others

OptionWhy not, for now
openSUSE MicroOSStrong, but updates are package-based, so we control less of what each machine gets.
ArchCurrent Hyprland, but no SELinux, no signed boot chain and no mature image updates. All of that would be our work.
NixOSRollbacks are great, but there's no verified read-only system and it adds a whole configuration language.
systemd image toolsThe best boot-chain design, but young: an upstream change broke KDE Linux updates in March 2026.
02 / pipeline

The update loop.
Every night.

Every change, and every upstream fix, goes through the same path before it reaches a machine. Promotion moves the exact tested image. Nothing is rebuilt.

GitHub Actions workflows

ci.yml

Rust: format, lint, tests on x86 and ARM, licenses and advisories, harness replay tests.

every PR · merge queue
image.yml

Build the image for both architectures, shrink update size (rechunk), push to GHCR, sign with our key, attach build provenance and the SBOM, scan for vulnerabilities.

merge · nightly · base bump
boot-test.yml

Boot the image in a KVM virtual machine: services up, desktop starts, a model answers, no SELinux denials, upgrade from the last stable, roll back.

after every image
eval.yml

The AI test suite. Replay tests on every PR. A small model on CPU for AI changes. The full suite nightly on a GPU machine. Any drop blocks the merge.

PR · nightly
disk.yml

Build the ISO and disk images, install the ISO unattended in a VM, sign checksums, upload to R2 storage and the GitHub release.

release tags · weekly
release.yml

Changelog and version from commit messages. Promotes :testing to :beta to :stable by retagging the same image, with a manual approval step.

main · manual approval

Protected main

Merge queue, required checks, signed commits, no force-push. Actions pinned by hash.

Signed and enforced

Every machine refuses an image that isn't signed with our key. CI tests that refusal.

Parts list per build

An SBOM is attached to every image. trip bom reads it on the machine.

Testing on your Mac and your laptop

Your Mac is an Apple M5. It can't run an x86 operating system at a useful speed, because it would have to emulate the whole processor. So we also build an ARM version of Tripppin. It runs natively and fast on the Mac for everyday development. Anything that depends on x86 hardware is tested in CI and on your laptop.

On the Mac, every day

  1. A Lima virtual machine runs Fedora for ARM. It builds images and boots them with bcvk.
  2. Change Rust code, build, copy the binary into a running VM, restart the service. Seconds, no image rebuild.
  3. Full image: build, boot a throwaway VM, test, exit.
  4. UTM 5 shows the real Hyprland desktop on the ARM build, with GPU acceleration.

On the x86 laptop, per release

  1. Download the ISO from CI and write it to USB with Fedora Media Writer. Avoid Ventoy, which hides Secure Boot issues.
  2. Install to a spare disk with Secure Boot on.
  3. Run the hardware checklist: Wi-Fi, suspend ×10, GPU and model speed, displays, audio, battery, touchpad.
  4. Drill: install a deliberately broken update and confirm it rolls back.
# the fast loop, inside the Lima VM on the Mac
$ podman build -t localhost/tripppin .
$ bcvk ephemeral run-ssh localhost/tripppin     # boots it, gone on exit
$ cargo build -p harness && sudo bootc usr-overlay && rsync … && systemctl restart trip-harness

04 / harness

Security by construction.
The verifier is a backup.

Research in 2026 shows every AI-based defense can be broken by a determined attacker. So the hard boundary is code. The AI verifier is an extra layer on top.

Planner never reads untrusted text

Web pages and files go to a separate reader with no tools. It returns typed values like a date, a yes/no or a short string. Based on Google DeepMind's CaMeL and Microsoft's FIDES.

Rule of two, in code

A session can mix two of: untrusted input, private data, changes or sending out. All three means you're asked. Meta's published rule.

Verifier for intent

Checks "did they ask for this?" on actions the policy already allows. It reduces mistakes; it isn't the wall.

Fail closed

Each tool runs in bubblewrap with Landlock and seccomp, network off by default. No sandbox, no run. The same model as Codex CLI and Claude Code.

06 / reliability

What keeps it
from breaking.

Pin everything

Base image digest, llama.cpp build, model files, Hyprland version, Actions. Upgrades arrive as reviewed PRs.

Promote, never rebuild

Stable is the exact image that passed testing, retagged.

Automatic rollback

greenboot checks services, desktop, GPU and network after every update.

Evals gate merges

Any drop in AI accuracy, or any successful attack, blocks the change.

Everything logged

Every model call and tool call is logged, and the logs double as replay tests.

Hardware decides

No beta ships without passing the laptop checklist.

Risks we're carrying

Hyprland packaging

Fedora stopped shipping it and community builds look abandoned. We maintain it. Fallback: Sway, which Fedora ships.

Signature enforcement

Some projects report problems enforcing signed images. CI tests this on every build.

Image size

A desktop ISO is over GitHub's 2 GB file limit, so ISOs go to R2 storage.

Twice-yearly Fedora rebase

Each new Fedora version goes through the same loop and soaks longer on :testing.

Verified boot is new

Fedora's fully sealed boot chain is still experimental. We ship standard Secure Boot and adopt sealed boot when it's stable.

NVIDIA

Driver signing needs a one-time key enrollment that some laptops handle badly. Separate image, tested separately.
